### Задача 1. Обработка больших данных в реальном времени

**Парадигма:** Императивная.
**Язык программирования:** C++.
**Обоснование:**
* Кадры идут непрерывно, объем - больше 3 гигабайт в секунду. Если использовать язык вроде Python, программа будет периодически «зависать» для автоматической работы сборщика мусора, из-за чего часть кадров просто потеряется.
* C++ позволяет напрямую отдавать команды GPU и процессору, чтобы проверять кадры математическими формулами на лету.
* Памятью управляет сам программист, и если руки прямые (не как у меня), то программа не упадет.
### Задача 2. Прототип ML-сервиса для прогноза погодных условий

**Парадигма**: Мультипарадигменная (процедурный подход + ООП).
**Язык программирования:** Python.
**Обоснование:**
* В Python уже есть всё необходимое для машинного обучения (`pandas`, `scikit-learn` и тд). Никакие сложные формулы не нужно писать вручную.
* Код пишется быстро, что идеально для прототипа. Попробовать другую модель прогноза погоды можно буквально в 2-3 строчки.
* Сервис считает прогноз всего несколько раз в сутки, поэтому сверхвысокая скорость выполнения программы здесь не требуется.

### Задача 3. Интерактивный UI для торгового терминала

**Парадигма:** Реактивная и компонентная (декларативная).
**Язык программирования:** TypeScript (в связке с React или Solid).
**Обоснование:**
* В терминале 50+ виджетов. Реактивный подход работает так: пришла новая цена по акции - автоматически обновилась только одна нужная цифра, а не вся страница целиком. Это дает отклик быстрее.
* Браузер исполняет только JS-стек. Чистый JavaScript при неверном формате пакета с биржи вызовет TypeError в рантайме и «уронит» весь терминал. TypeScript гарантирует строгие контракты данных еще до запуска кода.
* Интерфейс разбит на независимые кусочки (компоненты), каждый из которых легко проверить тестами по отдельности.
### Задача 4. Прошивка для устройства регистрации температуры

**Парадигма:** Процедурная (структурная).
**Язык программирования:** C.
**Обоснование:**    
* У датчика всего 32 килобайта оперативной памяти. У языка C нет «тяжелых» надстроек, он оставляет максимум места для самой логики.
* C умеет напрямую читать и записывать данные в физические регистры микроконтроллера.
* Компилятор языка С существует практически под любой микроконтроллер в мире, поэтому код легко перенести на другую микросхему.
